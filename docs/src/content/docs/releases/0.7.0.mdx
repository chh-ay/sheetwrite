<Note>
  0.7.0 is the next release and is not published yet. These notes track the changes already
  merged for it.
</Note>

Sheetwrite 0.7.0 turns a workbook into an analysis tool. Tables relate to each other in a data
model, measures calculate over it, and dashboards put pivots, slicers, PivotCharts and KPI cards
on one sheet. Sort moves the cells, as Excel's Sort does. Formulas read other workbooks, saved
queries refresh tables from your sources, and version history saves, compares and restores
versions. Editing works as in Excel: AutoFilter, cut and paste that moves cells, Paste Special,
Data Validation, Format Cells, Excel's keys with a panel to change them, and AutoComplete. Formula
assist suggests the rest of a formula in the formula bar. Every add-on now installs through one
call. Read the [breaking changes](#breaking-changes) before you upgrade.

## Analysis

### Data model

- Workbook tables relate one-to-many by stable table and column IDs, with undoable, synced
  `setRelationship` and `removeRelationship` operations.
  `SheetwriteStore.getRelationshipStatus(id)` reports unmatched keys, duplicate lookup keys,
  type mismatches and removed columns.
- Pivot tables use fields from related tables with the `{ model: { table, fields } }` source.
  The pivot field list shows the columns of related tables, and adding one turns a table pivot
  into a model pivot in one undo step.
- Data › Data Tools has **Data Model**, **Relationships** and **Measures** panels.

### Measures

- Measures are formulas over model columns, calculated in the filter context of each pivot cell,
  with a `{ measure }` value field and `setMeasure` / `removeMeasure` operations.
- Measures read related tables, refer to other measures by `[Name]`, follow renames, and
  `GETPIVOTDATA` reads them by name.
- `CALCULATE(expression, filter, …)` with column comparisons and `ALL(Table[Column])` changes
  the filter context.

### Dashboards

- Dashboard sheets (`kind: "dashboard"`) hold pivot, slicer, chart and KPI items on a 12-column
  grid. Items move and resize with the mouse and the keyboard, and Insert › New Dashboard adds
  one.
- Slicers filter every pivot whose table reaches the slicer column through relationships, and
  dim or hide values that no row has under the other slicers.
- PivotCharts and KPI cards: a chart item charts a pivot, and a KPI card shows one measure in
  the slicers' filter context.
- XLSX export writes each dashboard as a worksheet of its current values, with PivotCharts as
  native charts, and the dashboard opens as a dashboard again.

### Charts

- Charts over a pivot plot its leaf items, as Excel PivotCharts do, and can plot only some of
  its values, measures included.
- Multi-level category labels, as Excel draws them, kept in XLSX as `c:multiLvlStrRef`.
- XLSX import and export read and write Excel column, bar, line, area, pie, doughnut and scatter
  charts.

## Data

### Sort in place

- `store.sortRange` and `grid.sortRange` sort the cells, as Excel does: one undoable, synced
  change with the `permuteRows` operation and the `"sort"` commit reason. Formulas, merged
  cells, spill ranges and tables follow Excel's rules.
- Sort A to Z and Sort Z to A sort in place from the ribbon, the toolbar and the column menu.
  Data › Custom Sort opens a Sort panel with sort levels, a header row and a "Sort view only"
  option.
- Sorts use Excel's sort order: case-insensitive text in Excel's character order, errors after
  logical values, and blanks last in both directions.

### Linked workbooks

- Formulas accept references to other workbooks, such as `[Budget.xlsx]Annual!C10`, and to
  their defined names, such as `Budget.xlsx!Total`. They show the values the link saved, or
  `#REF!` without them.
- XLSX import keeps external links and the values Excel saved, and export writes them back.
- `externalLinksAddon({ resolve })` updates links from your resolver, points them at another
  workbook or breaks them into values, as one undoable change. Data › Queries & Connections ›
  Edit Links runs the same commands.

### Saved queries

- The optional `@sheetwrite/queries` package is a columnar query engine for CSV, JSON and typed
  host batches, in a lazily loaded 85 KB gzip WebAssembly module.
- Saved workbook queries refresh into workbook tables through `queriesAddon({ fetchSource })`:
  one undoable, synced transaction per refresh, with sources loaded only through your callback.
- Data › Get Data, Refresh All and Queries & Connections in the ribbon and toolbar. XLSX keeps
  saved queries as Power Query M.

### Version history

- `historyAddon()` adds Review › Version History and Save Version: save named versions, compare
  a version with the current document, preview it read-only, and restore the workbook, a sheet
  or a range.
- `HistoryArchive` stores versions in content-addressed chunks through a
  `HistoryStorageAdapter` or the built-in IndexedDB adapter. `diffVersions` pages changed cells
  with their authors. A 17 KB gzip WebAssembly kernel computes the comparison and loads only
  when one opens.
- `SyncCoordinatorOptions.authorId` records who made each change.

## Formulas

- Defined-name formulas, named LAMBDAs and a Name Manager.
- Formula help in the cell editor and the formula bar: autocomplete, an argument guide, live
  syntax errors, reference colours and Formulas › Explain Formula. Alt+Enter adds a line break, and both
  editors grow to eight lines.
- Formula assist, the new `@sheetwrite/formula-assist` package, shows the likely rest of a
  formula as ghost text in the formula bar, only when it is at least 90% sure. Tab takes it,
  Ctrl+→ (⌥→ on macOS) takes one word, Esc hides it, and the ranges it names get a faint fill.
  On a held-out set of real workbooks it saves 38.5% of keystrokes, with 2.6% of suggestions
  wrong. See [Formula assist](/docs/features/formulas/formula-assist/).
- Custom JavaScript functions with metadata install with `functionsAddon([...])` and appear in
  Formulas › Insert Function.
- The full engine adds Excel's engineering, complex number, Bessel, `CONVERT`, remaining
  financial, Excel 2007 statistics, byte-width text and `GETPIVOTDATA` functions. Both engines
  add 30 math functions, `LOOKUP`, `TRIMRANGE`, the `A` statistics and the information
  functions. See [Excel function coverage](/docs/reference/excel-function-coverage/).

## Grid and editing

- The toolbar, the full ribbon and a new compact ribbon (`config.ribbon: { mode: "compact" }`)
  render one command model.
- File › Import XLSX opens a workbook in the current grid, and `grid.importWorkbook` replaces
  the document without recreating the grid.
- `grid.trimMemory()` gives back memory an open grid can build again.
- Moving rows or columns moves the cells, as Excel's Insert Cut Cells does, and every reference
  follows them.
- `grid.sheetRowOf` and `grid.viewRowOf` map between view rows and sheet rows, and the
  `edit-begin`, `edit-commit` and `selection` events carry the sheet address too.

## Excel editing

### Filter, cut and paste

- **AutoFilter**: Data › Filter or Ctrl+Shift+L puts filter buttons on a header row. A button, or
  Alt+Down on a header cell, opens Excel's dropdown: sort, Number, Text and Date Filters with
  custom conditions, and a searchable value list with row counts. Date columns group by year,
  month and day. Each change is one undo step that syncs, and XLSX keeps the filter.
- **Cut and paste moves cells**: cut marks the cells with a moving border, and the paste moves
  their values, formulas, formats, notes, links, merged cells and rules. Every formula, name and
  chart that refers to them follows, as one undo step and one `moveCells` operation.
- **Paste Special**: Ctrl+Alt+V, Home › Paste and the context menu open Excel's dialog, with every
  Paste choice, Add, Subtract, Multiply, Divide, Skip blanks, Transpose and Paste Link. Paste
  Options paste Values, Formulas, Formatting, Transpose or Paste Link in one click.
- **Fill**: the fill handle continues Excel's series, shows each new value while it drags, and
  offers Auto Fill Options after the fill.
- **Insert and Delete** shift cells right, down, left or up, as in Excel.

### Validation and formats

- **Data Validation**: Data › Data Validation opens Excel's dialog with Settings, Input Message
  and Error Alert. Rules take every Excel type, lists from a range or a defined name, and formula
  bounds. A list cell shows a dropdown arrow, typing filters its list, and a rejected value shows
  Excel's Stop, Warning or Information alert.
- **Format Cells**: Ctrl+1 opens a dialog with Number, Alignment, Font, Border and Fill, and the
  selected cells preview the new format until OK or Cancel. Fraction and Text formats work as in
  Excel.

### Keys and typing

- **Excel's keys**: the active cell, Enter and Tab, the editor's Enter, Edit and Point modes, and
  Excel's format, fill, hide, insert and sheet keys.
- **Keyboard shortcuts panel**: `config.keyboardSettings: true` adds a panel where users search
  commands by name or keys, record, swap and reset keys, and export them. The grid emits
  `key-bindings-change` for you to store.
- **AutoComplete**: typing a text entry completes it from the column, and several matches show
  in a list. Alt+Down opens Excel's Pick From Drop-down List.
- **Find**: Excel's wildcards and Find Options, Find All, workbook search, and a preview of what
  Replace all will change.
- **Formula editor**: the formula list offers names, tables, columns and argument values; a
  formula that doesn't parse is refused with Excel's message; live errors offer a one-click fix.

## Performance

0.7.0 is faster than 0.6.1 in every group below. Recalculation is faster on average, and large
`INDEX`/`MATCH` lookups are up to 125 times faster. The lanes give the exact figures.

Each lane compares 0.7.0 with 0.6.1 on the same machine: the further right the mark, the larger
the gain. "0.25 of the time" means four times faster. A range covers both machines, or the
default and the full engine.

### Formulas and recalculation

`INDEX`/`MATCH` lookups read only the cell they return: 200 lookups over 100,000 rows take
0.008 of the time on the Mac and 0.011 on Linux.

```perf-lanes diagram title="Formulas and recalculation, 0.7.0 against 0.6.1" base="0.6.1"
200 `INDEX`/`MATCH` lookups over 100,000 rows | Linux: 0.011 of the time | Mac: 0.008 of the time
Append a table row | Range: about 60× faster
Redefine a name 100,000 formulas use | Linux: 19 ms instead of 491 ms
`COUNTIF` with a number criterion, 100k cells | Range: 11.5–18× faster
`SUM` over two 100k ranges | Range: 2.15–6.62× faster
A `LET` in every row | Range: 0.17–0.22 of the time
`MAP`, `REDUCE`, `BYROW` and named `LAMBDA` calls | Range: 0.41–0.64 of the time
Recalculation, average of 53 workloads | Range: 0.837–0.861 of the time
The same, with flat dependency arrays | Range: 0.835–0.912 of the time
```

- The dependency index for 100k formulas shrinks from 7.67 MB to 1.21 MB.

### Charts and pivots

With 20,000 formula-backed charts, an unrelated edit and the chart refresh take 0.006 ms instead
of 20.2 ms on the Mac and 0.016 ms instead of 47.3 ms on Linux.

```perf-lanes diagram title="Charts and pivots, 0.7.0 against 0.6.1" base="0.6.1"
Unrelated edit with 20,000 formula-backed charts | Linux: 0.016 ms instead of 47.3 ms | Mac: 0.006 ms instead of 20.2 ms
Edit on another sheet, PivotTable field list open | Mac: 12.95 µs instead of 1.629 ms
Pivot of measures over 100,000 rows | Range: 0.66–0.71 of the time
```

- `GETPIVOTDATA` recalculates only when its pivot changes, as in Excel.

### Paged and large data

A row insert in a 1,000,000-row paged sheet takes 0.0136–0.0221 of the time.

```perf-lanes diagram title="Paged and large data, 0.7.0 against 0.6.1" base="0.6.1"
Row insert, 1,000,000-row paged sheet | Range: 0.0136–0.0221 of the time
Drain 10,000 acknowledged edits | Mac: 0.246 ms instead of 4.004 ms
Admit a 1,000,000-cell `setBlock` | Linux: 65 ms instead of 617 ms | Mac: 17 ms instead of 212 ms
Range formulas over loaded pages | Range: 3.0–3.1× faster
```

- After a fast fling, cells show "loading" up to 74% less.

### Grid and editing

Setting 100,000 row heights one at a time takes 0.49 s instead of 151.8 s on the Mac and
2.05 s instead of 340.8 s on Linux.

```perf-lanes diagram title="Grid and editing, 0.7.0 against 0.6.1" base="0.6.1"
Set 100,000 row heights one at a time | Linux: 2.05 s instead of 340.8 s | Mac: 0.49 s instead of 151.8 s
Paint a wrapped cell of 20,000 characters | Mac: 0.175 ms instead of 0.887 ms
Sort command on 1,000–4,000 numbers | Range: 0.329–0.509 of the work
```

- Scrolling with the cell editor open forces no style or layout work.

### Import and export

CSV import takes 7.3% less time on the Mac and 11.0% less on Linux.

```perf-lanes diagram title="Import and export, 0.7.0 against 0.6.1" base="0.6.1"
Load formulas | Range: 1.21–1.46× faster
CSV import | Linux: 11.0% less time | Mac: 7.3% less time
XLSX export of 100,000 formulas | Linux: 1,030 ms instead of 1,053 ms | Mac: 481 ms instead of 491 ms
```

### Download size

`grid.css`, the one stylesheet part every grid needs, is 4,666 B, where the old stylesheet was
89,452 B.

- Shared sorts make the engines 13,307 B (default) and 16,248 B (full) Brotli smaller, and
  writing number text without Rust's float formatting saves 6,784–7,113 B (default) and
  5,561–5,563 B (full).
- The query engine (85,351 B gzip) and the version comparison kernel (16,646 B gzip) load only
  when they are used.

## Breaking changes

The [0.7.0 upgrade guide](/docs/start/upgrade-to-0-7-0/) lists every change with its
replacement. The changes most apps meet:

### Add-ons install through `initSheetwrite`

<Compare before="0.6" after="0.7.0">

```js partial="0.6 code; these imports and arguments no longer exist"
import "@sheetwrite/charts/register";
import "@sheetwrite/xlsx/register";
import * as formulas from "@sheetwrite/formulas";

await initSheetwrite(undefined, formulas);
```

```ts compile
import { chartsAddon } from "@sheetwrite/charts";
import { initSheetwrite } from "@sheetwrite/core";
import * as formulas from "@sheetwrite/formulas";
import { xlsxAddon } from "@sheetwrite/xlsx";

await initSheetwrite({
  engine: formulas,
  addons: [chartsAddon(), xlsxAddon()],
});
```

</Compare>

`registerChartsBackend`, `registerXlsxBackends`, the chart and XLSX backend setters and the
positional `initSheetwrite(source, engine)` are removed with the `/register` imports.

### Sort moves the cells

<Compare before="0.6" after="0.7.0">

```js partial="0.6 code"
// Sorted the view only.
grid.sortBy(2, true);
grid.setSort([{ col: 2, ascending: true }]);
```

```ts compile
import type { Grid } from "@sheetwrite/core";

export function sortByRegion(grid: Grid) {
  // Sorts the cells, as Excel does.
  grid.sortBy(2, true);
  // The display-only sort.
  grid.setViewSort([{ col: 2, ascending: true }]);
}
```

</Compare>

`store.sortBy`, `store.sortByMulti`, `grid.setSort` and `grid.sortByMulti` are removed. An
imported worksheet `sortState` is kept, not applied as a view sort.

### Revisions move to version history

<Compare before="0.6" after="0.7.0">

```js partial="0.6 code"
const revisions = new RevisionCoordinator(adapter, { documentId, serverVersion });
const [latest] = await revisions.list();
await revisions.restore(latest.version, crypto.randomUUID());
```

```ts compile
import type { Grid, SyncCoordinator } from "@sheetwrite/core";
import { HistoryArchive, type HistoryStorageAdapter } from "@sheetwrite/core/history";

export async function restoreLatest(
  grid: Grid,
  sync: SyncCoordinator,
  storage: HistoryStorageAdapter,
) {
  const archive = await HistoryArchive.open({ documentId: "workbook-42", storage });
  const { versions } = await archive.listVersions({ maxEntries: 20 });
  const latest = versions[0];
  if (latest === undefined) return;
  return archive.restoreVersion(grid, latest.id, { kind: "workbook" }, { sync });
}
```

</Compare>

### Chart views are read-only

`ChartView.chart` is now the store's own definition, typed `ReadonlyChartDefinition`, and
development builds freeze it. Edit a copy from `grid.getCharts(sheet)` and commit it with
`grid.setChart`. The result of `rebaseDocumentOperations` can hold your own operations, so treat
it as read-only too. See [Chart views are read-only](/docs/start/upgrade-to-0-7-0/#chart-views-are-read-only).

### Removed engine bindings

Direct `@sheetwrite/wasm` and `@sheetwrite/formulas` users must replace these bindings:

| Removed | Replacement |
| --- | --- |
| `CellStore.setColumnNumbers`, `setColumnStrings`, `setColumnStringsPacked` | `setColumnBlockPacked`, `setBlockPacked` or `setSparseBlock` |
| `DiffKernel.clearPage` | Consume the page arrays; the next `compare` starts a new page |
| `DiffKernel.pageLength` | Read the length of a returned page array |

The scalar setters and `clearCell`, `CellStore.rowCount` / `colCount`, and
`WindowView.nRows` / `nCols` remain public APIs.

`setSheetName` now returns whether it named the sheet. Like `renameSheet`, it refuses an empty
name, a name another sheet holds in any case, and another sheet's id.

### Excel's keys, search, paste and validation

- New default keys, such as Ctrl+B, Ctrl+1 and Ctrl+Alt+V, throw `shortcut-conflict` for a host
  key that already uses one. Rebind the action or set it to `null`. See
  [Keyboard defaults](/docs/start/upgrade-to-0-7-0/#keyboard-defaults).
- A selection's active cell is the cell it started from, reported as `active`.
- Cut no longer empties its cells; the paste moves them with the new `moveCells` operation, and
  the `"cut"` commit reason is gone. Servers that check operation kinds must accept it.
- Search treats `*` and `?` as wildcards, looks in formulas unless `lookIn: "values"`, and
  searches only a selection of more than one cell.
- A paste brings the copied cells' validation rules. `paste.keepValidation: true` keeps the
  target's rules, as 0.6 did.
- `DataValidationCondition`, `ColumnFilter` and `SheetNameIssueCode` have new members.

### Errors and cancellation

- Bad input and passed limits throw a `SheetwriteError` (`invalid-argument`, `not-found`,
  `invalid-limits`) instead of `RangeError`, `TypeError` or `Error`.
- Aborted XLSX, CSV, comment and sync calls reject with the signal's reason.
- A WebAssembly trap throws `engine-failed` and makes every grid on that engine read-only.

### Direct XLSX formula conversion

Direct callers of `@sheetwrite/wasm` or `@sheetwrite/formulas` now pass joined
sources, cumulative UTF-16 ends and a changed-index buffer to `convertXlsxFormulas`,
which returns only the changed formulas. The scalar `formulaToXlsx` and `formulaFromXlsx`
exports are removed; use a one-source batch instead. Core's
`XlsxFormulaEngine.convert` keeps its array interface. See
[Direct engine calls](/docs/start/upgrade-to-0-7-0/#direct-engine-calls).
