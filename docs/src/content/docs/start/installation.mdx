`styles.css` imports every part of the stylesheet. To ship less CSS, import only the parts your grid uses from `styles/`; see [Stylesheet parts](/docs/features/formatting/styles/#stylesheet-parts).

## Server-rendered host boundaries

The adapter host, its `Grid`, and WASM initialization are client-owned. Server rendering may produce surrounding layout and fallback content, but it must not instantiate a Sheetwrite component or call `createGrid`.

**Next.js App Router:** put the adapter import and component in a module whose first directive is `"use client"`. Import `@sheetwrite/react/styles.css` once from the root layout. The production fixture builds a static Next route, hydrates it in Chromium, then proves ready, edit, input reset, and unmount using the adapter's zero-argument initializer.

**Nuxt:** render `@sheetwrite/vue` from a `.client.vue` component or inside Nuxt's `<ClientOnly>` boundary, and load `@sheetwrite/vue/styles.css` through the app-level `css` configuration. Nuxt is not currently in the release runtime matrix, so this boundary is required and server-side component execution is not claimed as supported.

**SvelteKit:** make the containing route client-rendered with `export const ssr = false`, or create the adapter only from `onMount` when the rest of the route must stay server-rendered. Import `@sheetwrite/svelte/styles.css` from the client-owned component or app stylesheet. SvelteKit is not currently in the release runtime matrix; direct SSR of the adapter is not claimed as supported.

## Runtime initialization

With `@sheetwrite/core`, call `initSheetwrite()` with no arguments. You can call it more than once: calls at the same time share one start, a failed start can be tried again, and calls after a successful start do nothing. Framework adapters call the same initializer on mount.

Pass a source only for unsupported bundlers, public-asset policies, or controlled delivery:

```ts prelude="wasm" partial="requires an explicit asset source" title="Explicit WASM source"
await initSheetwrite({ source });
```

Accepted sources are `BufferSource | URL | string | Request | WebAssembly.Module`. The raw binary remains exported as `@sheetwrite/wasm/wasm`.

```ts prelude="wasm" partial="requires surrounding host state" title="Explicit asset examples"
// Vite-family URL
import wasmUrl from "@sheetwrite/wasm/wasm?url";
await initSheetwrite({ source: wasmUrl });

// webpack asset URL
await initSheetwrite({ source: new URL("@sheetwrite/wasm/wasm", import.meta.url) });

// Public-copy fallback
await initSheetwrite({ source: "/sheetwrite_wasm_bg.wasm" });
```

webpack and Next.js need no `IgnorePlugin`; package export conditions keep Node filesystem code out of browser graphs.

## Full formula engine

By default, `@sheetwrite/core` uses `@sheetwrite/wasm`. This engine has the standard function set and the smallest download. Install `@sheetwrite/formulas` when the app needs the analysis families: distributions and statistics, regression, finance, dates, text and regex, database, matrices, reshaping, `LAMBDA` helpers, and `GROUPBY`/`PIVOTBY`. It uses the same engine code, with more functions and a larger download. The [analysis formulas guide](/docs/features/formulas/analysis-formulas/) shows each family with examples. [Choose an engine](/docs/start/choose-an-engine/) by its functions and download size; the [formula engine performance](/docs/performance/formula-engine/#choose-a-formula-engine) page compares the builds.

```sh verify
npm install @sheetwrite/core @sheetwrite/formulas
```

Select the engine one time, before the app creates a grid or a store, and before a framework adapter mounts:

```ts compile title="Select the full formula engine"
import { initSheetwrite } from "@sheetwrite/core";
import * as formulas from "@sheetwrite/formulas";

await initSheetwrite({ engine: formulas });
```

- An app uses one engine. After initialization starts, the engine cannot change. A call that selects a different engine rejects.
- Later calls to `initSheetwrite()` without an engine keep the selected engine. Framework adapters make this call when they mount.
- The default engine returns `#NAME?` for the analysis functions, and formula assist does not suggest them. An import of `@sheetwrite/formulas` does not select the engine.
- The [formula function contract](/docs/reference/formula-functions/) shows which build has each function.

## Failure UI and retries

React accepts `fallback`; Vue and Svelte use fallback content or slots. Initialization failures reach `onInitializationError` or Vue's `initialization-error`. A changed explicit source or remount can retry after failure.

### When the WebAssembly file does not load

`initSheetwrite()` rejects with a `SheetwriteError` whose `code` is `"initialization-failed"`. Its `message` is the browser's own error text, and its `cause` is the browser's error. Find that text in the table below. The texts come from Chromium (Chrome, Edge), Firefox and Safari's WebKit in November 2026; other browser versions can word them differently.

| Cause | Chromium | Firefox | Safari | Fix |
| --- | --- | --- | --- | --- |
| The server answers 404 for the `.wasm` file. | `Failed to execute 'compile' on 'WebAssembly': HTTP status code is not ok` | `WebAssembly: Response has unsupported MIME type 'text/html' expected 'application/wasm'` | `Unexpected response MIME type. Expected 'application/wasm'` | Open the `.wasm` URL from the network panel. If it is missing, make your bundler emit the file, or copy it to a public folder and pass that URL as `source`. |
| The server answers with an HTML page instead of the file, for example a single-page-app fallback. | `WebAssembly.instantiate(): expected magic word 00 61 73 6d, found 3c 21 64 6f @+0` | `wasm validation error: at offset 4: failed to match magic number` | `WebAssembly.Module doesn't parse at byte 0: module doesn't start with '\0asm'` | Exclude `.wasm` files from the fallback rewrite. The URL must download a binary that starts with the bytes `00 61 73 6d`. |
| A Content Security Policy blocks WebAssembly. | `Compiling or instantiating WebAssembly module violates the following Content Security policy directive because 'unsafe-eval' is not an allowed source of script` | `call to WebAssembly.instantiateStreaming() blocked by CSP` | `Refused to create a WebAssembly object because 'unsafe-eval' or 'wasm-unsafe-eval' is not an allowed source of script` | Add `'wasm-unsafe-eval'` to the `script-src` directive. It allows WebAssembly without allowing `eval()`. |
| The request fails: the browser is offline, or an extension, proxy or CORS rule blocks it. | `Failed to fetch` | `NetworkError when attempting to fetch resource.` | `Load failed` | Find the failed request in the network panel and remove the block. A failed start can be tried again: call `initSheetwrite()` again, or remount the component. |

A wrong MIME type alone does not stop the load. When the server sends the file as `application/octet-stream` or another type, the browser cannot compile it while it downloads, and the console shows this warning: "`WebAssembly.instantiateStreaming` failed because your server does not serve Wasm with `application/wasm` MIME type. Falling back to `WebAssembly.instantiate` which is slower." The grid still starts. Serve `.wasm` files as `application/wasm` to remove the warning and make the start faster.
